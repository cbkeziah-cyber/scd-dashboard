Executive Summary

What Was Built & Why

Burke's Pharmacy Group operates four locations across the South Carolina Lowcountry — two pharmacies and two durable medical equipment centers. Despite strong community presence, the group lacked a centralized view of their digital performance and had no streamlined way for patients to transfer prescriptions, book appointments, or engage online.


This project delivered two interconnected solutions: a live SEO & analytics dashboard giving management real-time visibility into search rankings, web traffic, and Wix e-commerce performance — and a custom web page system for their Wix site that modernizes the patient experience across all locations, optimized for both desktop and mobile.

Overview Dashboard

Real-time stats from Google Search Console (clicks, impressions, CTR, avg. position) and GA4 (sessions, pageviews, bounce rate) displayed side by side with traffic trend charts.

🔍

On-Page SEO Editor

Pulls live product data from the Wix Stores API. Each product shows its SEO score and flags issues. Managers can edit meta titles, descriptions, and product copy directly and save back to Wix via PATCH API.

🛒

Ecommerce Tracking

Integrates with the Wix Stores v1 API to pull revenue, order counts, and product performance — giving the team a unified view alongside their organic traffic data.

📅

Date Range Controls

Header-level date picker lets users switch between 7, 14, 28, and 90-day windows. All widgets re-query the APIs and refresh simultaneously.

🔑

Google OAuth 2.0

One-click sign-in via Google Identity Services. Access token stored in localStorage. Connects to both Search Console and Analytics APIs with a single auth flow.

🛠️

Server-Side Wix Proxy

An Express.js proxy layer on the server bypasses Wix's browser CORS restrictions, remapping client headers server-side so all Wix API calls succeed without exposing keys.

Technical Architecture

How It Works

The platform is split into two layers: a React SPA served by an Express.js server (acting as both static host and API proxy), and standalone HTML/CSS pages embedded into the existing Wix CMS.

User visits dashboard URL

Railway serves the production-built React app from the Express static server. No Vite dev server — single bundled JS file eliminates cache collision issues.

Google OAuth sign-in

Google Identity Services issues an access token via implicit flow. Token stored in localStorage and automatically attached to all GSC and GA4 API calls.

Wix API calls routed through proxy

Browser sends requests to /wix-api/* on the same origin. Express intercepts, remaps headers (x-wix-site-id → wix-site-id), and forwards to Wix's servers — bypassing browser CORS restrictions.

On-Page SEO edits saved live

Manager edits a product's meta title or description in the dashboard modal. Dashboard sends a PATCH request via the proxy to the Wix Stores v1 API, updating the product in real time. The product list refreshes automatically.

Web pages embedded in Wix

HTML pages are pasted into Wix's Custom HTML embed widget. All CSS is scoped with unique class names to prevent Wix stylesheet conflicts. No inline forms — all CTAs link out to RxLocal, JotForm, or Railway-hosted tools.
